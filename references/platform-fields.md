# 平台字段速查 / Platform field notes

平台限制会随 CLI 和平台页面变化。每次运行仍要读取 `prepare`/`schema fields`，以下只记录决策映射和当前常见约束。

| 平台 | 标题/简介 | 短标题 | 标签或动态字段 | 原创与草稿 |
| --- | --- | --- | --- | --- |
| 视频号 | 标题通常最多 80 字；简介最多 1000 字，可含话题 | `short_title` 是独立字段；schema 可能给出 80，但页面实际限制需用草稿验证 | `horizontalCover` 与竖版 `cover` 分开；位置、合集、活动、商品、剧集用查询 | `createType=1` 原创，`2` 非原创；`pubType=0` 草稿，`1` 直接发布 |
| 小红书视频 | 标题通常最多 20 字；描述最多 1000 字 | 以当前 schema 为准 | `visibleType` 等必填项和账号能力要查询 | `createType`/声明字段以当前 schema 为准；先 dry-run |
| 哔哩哔哩视频 | 标题最多 80 字；简介最多 2000 字 | 通常没有视频号同名字段 | `tags` 必填数组，通常 1–10 个；`category` 为级联动态对象，必须查询候选 | `createType=1` 自制/原创，`2` 转载；`pubType=0` 草稿，`1` 直接发布 |

## 字段生成建议

- 标题：一个结论 + 一个具体对象，避免把全部脚本塞进标题。
- 短标题：先选 8–16 个字符的清晰版本，记录实际草稿是否接受；不要声称平台一定是 16 字。
- 简介：一句结论、两句要点、一个行动句，再添加 3–5 个与脚本直接相关的话题。
- 标签：从脚本中的实体、行业和问题抽取；B站 tags 按 schema 填字符串数组，分区 category 才是必须实时查询的对象数组。
- 原创：只有用户明确选择原创时才设置对应枚举；`pubType` 只表示草稿或直接发布。

动态对象必须保留 CLI 返回的完整结构（包括 `raw`，若 contract 要求），不能只凭显示名称手写。
